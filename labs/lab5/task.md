### Теоретичні положення

#### Патерн Singleton

Цей патерн гарантує, що для деякого класа можна створити тільки один екземпляр об'єкта. Для деяких типів об'єктів важливо, щоб впродовж роботи існував тільки один екземпляр об'єкта і забороняється навмисно чи помилково створювати інші екземпляри.

Класична реалізація класу Singleton. Для блокування створення інших об'єктів контролюється значення статичного члену — вказівника `p_instance`. Об'єкт створюється шляхом `new`.

Приклад оголошення класу у файлі `singleton.h`:

```cpp
class Singleton
{
private:
    static Singleton * p_instance;
    Singleton() {}
    Singleton( const Singleton& );
    Singleton& operator=( Singleton& );
public:
    static Singleton * getInstance();
    void Func(); // змістовна функція для клієнта
    // ... інші змістовні функції, потрібні для клієнта
};
```

Реалізація методу `getInstance()`:

```cpp
Singleton* Singleton::p_instance = nullptr;

Singleton* Singleton::getInstance()
{
    if (!p_instance)
        p_instance = new Singleton();
    return p_instance;
}
```

#### Singleton Меєрса

Альтернативна реалізація — статичний локальний об'єкт у функції `getInstance()`:

```cpp
class MyEditor
{
private:
    MyEditor() {}
    MyEditor(const MyEditor&) = delete;
    MyEditor& operator=(const MyEditor&) = delete;
public:
    static MyEditor& getInstance() {
        static MyEditor instance;  // створюється один раз
        return instance;
    }
};
```

Переваги: простота, автоматичне знищення, потокобезпека (C++11).

#### Немодальні вікна діалогу

На відміну від модальних (`DialogBox`), немодальні вікна не блокують батьківське вікно. Створюються функцією `CreateDialog`:

```cpp
HWND hWndDlg = NULL;

void ActivateModeless(HWND hWnd)
{
    if (hWndDlg)   // якщо вікно вже є — закриваємо
    {
        PostMessage(hWndDlg, WM_SYSCOMMAND, SC_CLOSE, 0);
        return;
    }
    hWndDlg = CreateDialog(hInst, MAKEINTRESOURCE(IDD_DIALOG1), hWnd, DlgProc);
}
```

Закриття — `DestroyWindow(hDlg)`, не `EndDialog`.

#### Багатовіконний інтерфейс

Програма складається, як мінімум, з двох частин:
- частина підтримки головного вікна (ввід та відображення об'єктів геометричних форм)
- частина підтримки окремого немодального діалогового вікна таблиці (список об'єктів)

#### Вікно таблиці

Множину об'єктів, які вводяться у головному вікні, потрібно відображати у таблиці — немодальному діалоговому вікні. Кожен рядок таблиці — опис геометричного об'єкта:

| Назва | x1 | y1 | x2 | y2 |
|-------|----|----|----|-----|
| Точка | 10 | 130 | 10 | 130 |
| Лінія | 45 | 23 | 400 | 327 |
| Еліпс | 123 | 304 | 257 | 412 |

При кожному додаванні нового об'єкта у головному вікні, інформація про нього автоматично з'являється у таблиці (новий рядок). Таблиця повинна мати скролінг по вертикалі.

#### Запис об'єктів у файл

Множину об'єктів потрібно записувати у файл. Рядок файлу містить п'ять полів: назва класу об'єкта та чотири координати (x1, y1, x2, y2). Поля відокремлюються символами табуляції:

```cpp
FILE* fout;
fopen_s(&fout, "myfile.txt", "wt");
if (fout) {
    fprintf(fout, "%s\t%d\t%d\t%d\t%d\n", name, x1, y1, x2, y2);
    fclose(fout);
}
```

### Варіанти завдань та основні вимоги

1. Для усіх варіантів завдань необхідно дотримуватися вимог та положень, викладених вище у порядку виконання роботи та методичних рекомендаціях.

2. Номер варіанту завдання дорівнює номеру зі списку студентів у журналі.
   - Студенти з **непарним номером** (1, 3, 5, ...) програмують глобальний статичний об'єкт класу `MyEditor` у вигляді **Singleton Меєрса**.
   - Студенти з **парним номером** (2, 4, 6, ...) програмують об'єкт класу `MyEditor` на основі **класичної реалізації Singleton**.

3. Усі кольори та стилі геометричних форм — як у попередній лаб. роботі №4.

4. Запрограмувати **вікно таблиці**. Для його відкриття та закриття передбачити окремий пункт меню. Вікно таблиці повинно автоматично закриватися при виході з програми.

5. Вікно таблиці — **немодальне** діалогове вікно. Може бути реалізоване на основі стандартного вікна списку або малюванням ліній і тексту функціями Windows API (`MoveToEx`, `LineTo`, `TextOut`).

6. Вікно таблиці програмується у **незалежному модулі** `my_table` (файли `my_table.cpp`, `my_table.h`, `my_table.rc`). У файлі `my_table.h` оголошується клас `MyTable`:

```cpp
class MyTable
{
    // ... члени класу
public:
    void Add(..);  // додавання у таблицю нового рядка з описом об'єкта
    // ... інші функції
};
```

7. Після вводу у головному вікні нового об'єкта обробник повідомлення `WM_LBUTTONUP` викликає `MyTable::Add()` для занесення у таблицю назви та координат нового об'єкта.

8. **Модуль `my_table` повинен бути самодостатнім та незалежним** від будь-якого з модулів програми. Він не може використовувати `#include` будь-який файл проєкту (окрім `framework.h`). Вікно таблиці — самодостатній компонент, який можна використовувати у інших проєктах.

9. Головний клас `MyEditor` (Singleton) інкапсулює масив об'єктів типу `Shape` та містить public інтерфейсні функції редактора. Оголошення — у `my_editor.h`.

10. Запис множини об'єктів у файл (текст, tab-separated: назва класу + x1, y1, x2, y2).

11. У звіті повинна бути схема успадкування класів — діаграма класів, та діаграма залежностей модулів.

#### Бонусні завдання (за бажанням)

1. При виділенні користувачем рядка у таблиці — підсвітка відповідного об'єкта у головному вікні.
2. При натисканні на об'єкт у головному вікні — виділення відповідного рядка у таблиці.
   - **Забороняється** робити нові залежності модуля `my_table` від інших `.cpp` файлів. Використати технологію Callback або патерни Observer/Listener.
3. Якщо програма не тільки записує у файл, а ще й здатна завантажити файл і відобразити об'єкти у головному вікні та вікні таблиці.
